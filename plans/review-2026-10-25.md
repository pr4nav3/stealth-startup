## What the Mac pass did, judged

Sound, and kept as is:

- **Accessibility address read** (`browser_macos.rs`): the page address only, never contents;
  cached path to the web area, 0.3 s AX timeout and a 150 ms search budget so a hung browser
  cannot stall the 1 s tick. Chrome is switched into accessibility mode, which costs Chrome
  some CPU and memory; acceptable, noted in known issues.
- **Sleep-aware session clock** (`SessionClock`): macOS `Instant` stops during sleep; the new
  clock uses `CLOCK_MONOTONIC` there and `Instant` elsewhere. Windows behaviour unchanged.
- **Schema v13**: strips invisible direction marks from stored app names without moving
  history between apps whose clean keys collide. All touched columns are `NOT NULL`, so the
  migration cannot trip on nulls. Tested both ways.
- **Zero-length span cleanup**, **pause-safe flagging**, **integrity check moves a damaged
  database aside**: each small and tested.
- **Workers in their own process group**, killed as a group; the webcam worker also exits
  when orphaned. Windows still uses the job object.
- **Voice runtime zips keep symlinks**; extraction refuses links that escape the runtime or
  that a later entry would write through. Dev worker overrides are ignored in release builds.
- **Silent recordings refused** (all samples below 40 of 32767): applies on Windows too, which
  is right (the Windows privacy switch also records silence).
- **Mac installer** (`scripts/install-mac.sh`): HTTPS only, checksum, certificate pinned by
  leaf hash, staged copy and atomic swap. Distribution choice is recorded in
  `plans/distribution.md`.

Changed behaviour on Windows worth knowing:

- Closing the main window now hides it on every OS (tray brings it back, Quit is in the tray).
- `PermissionState::Granted`, two automation stubs and a helper produced four compiler
  warnings on Windows; fixed.

## Fixed on `fix/post-mac-review`

1. **Starter voices speak.** 20 clips each for `derek` and `elise` ship in
   `src-tauri/voices/<id>/` and are copied into the starter profiles once (a marker keeps a
   deleted clip deleted; an existing clip for a line is kept). Before this a new user's first
   session with a starter voice was silent: the V1 milestone ("hear the voice") failed out of
   the box. Each clip was chosen from four seeded takes by duration against its text; the
   first round had several lines that dropped words. **Nobody has listened to them.**
2. **Voice page says why a clip failed**: the reason shows under Generate in red instead of a
   hover tooltip; a failed queue no longer disables Generate, the voice picker and page
   rebuilds; the lines after a failure no longer read "Queued".
3. **Clip time estimate**: "~90 s a clip" for every line became ~90 s for the first (model
   load) and ~15 s for each after. Measured: 3-6 s per clip once the worker is loaded.
   "Generate 5 missing" now says ~2½ min instead of ~7½ min.
4. **Empty Home no longer scrolls** at 920x760: the quote card's own text grew the card and
   the column (size containment fixes it), and the quote was never re-fitted after the
   webfont loaded or the window resized. The WebKit check now allows Home zero scroll.
5. Four Windows compiler warnings.
6. **Windows voice runtime rebuilt** with the current worker (311 MB zip and asset file in
   `build/voice-runtime/` on the Windows machine); installed through the app's own install
   code and made a clip from a cold start in 39 s. Ready to upload next to the Mac one.

## What is left for a release

Needs you (cannot be done by an agent here):

- **Listen to the 40 starter clips** (Settings > Voice > Clips for Starter Male / Female).
  Regenerate any that sound wrong; "Beta" in the Mom set is the known risk.
- **Publish the GitHub Releases**: the app (`v0.1.0` with the Mac zip and `.sha256`) and the
  `voice-runtime` pre-release (zip and manifest). Until then the Mac one-liner and every
  installed copy's voice download fail. Steps: `plans/distribution.md`.
- **Windows distribution decision**: direct download with SmartScreen warnings, or the
  Microsoft Store. Then freeze the Windows webcam worker and build the installer for it
  (the voice runtime is already rebuilt).
- **Windows live pass** with your running copy closed: a V2 session (Not today, Never a
  distraction), History with real weeks, a voice tone end to end, webcam session, quit and
  check no worker survives, and the close-to-hide window.
- **Back up the Mac signing certificate** (`~/supervisor-signing/` on the MacBook) into a
  password manager. Losing it silently drops every Mac user's permissions on the next update.
- **The repository is public** and named `stealth-startup`; every plan and the commit history
  are readable. Decide whether that is intended before announcing the installer.

Product weak spots, in order of how much they cost a new user:

1. **Cloning a voice is heavy**: a ~2 GB model download, 7 GB of RAM and 4 GB free, and the
   first clip's minute and a half. The starter clips now cover the first session; a custom
   voice is still a commitment.
2. **No installer on Windows**, which is half the target.
3. **Mac trust model**: a self-signed certificate and a `curl | sh` line work for technical
   users and skip Gatekeeper by design; a mainstream launch wants a Developer ID and
   notarization (Apple Developer Program).
4. **Phone detection sees only a phone in the camera's frame**; a phone in the lap is
   invisible.
5. **Windows close-to-hide gives no hint** that the app is still running.
6. Installed web apps (Chrome/Safari "Add to Dock") count as apps, not sites; Python GUI apps
   show as "Python"; Arc and Intel Macs untested or unsupported.

## Against the plan and the field

The V1 plan's promise is a familiar voice that catches drift, local only, with no blocking.
The branch now meets every V1 acceptance item in code on both OSes except installation on
Windows. It goes beyond V1 in two places the plan had deferred: exact websites (through the
OS, not an extension) and webcam phone detection (opt-in, frames never stored).

The field in 2026 splits three ways, and Supervisor sits between them:

- **Blockers** (Freedom, Cold Turkey, SelfControl, one sec, Screen Time, FocusMe): stop you
  opening things. Stronger enforcement; no feedback about what you actually did.
- **Trackers** (Rize, Timing): record and categorise all day. Rich reports; no in-the-moment
  push back, and always-on watching.
- **Nudgers** (Faahh, launched April 2026: a loud sound when you go idle): closest in spirit;
  generic sound, idle-only, no idea what is on screen.

Supervisor's wedge holds: a voice you chose, reacting to the specific distraction, during
sessions you started, with nothing leaving the machine; and phone-in-view detection, which
none of the above do. What the field does better: one-click install everywhere, a hard mode
for people who want enforcement, and cross-device (phone) coverage. A "lock in" mode that
blocks after repeated nudges would answer the first-class blocker users without changing the
local-first promise; it is a product decision, not built.
